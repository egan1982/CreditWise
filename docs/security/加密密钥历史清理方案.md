## 二、风险分级

| 场景 | 风险 | 说明 |
|------|:---:|------|
| 当前（两仓库私有） | 🟢 低 | 仓库不可公开访问，密钥未外泄 |
| 未来仓库公开/开源 | 🔴 高 | 任何人 clone 历史即可提取密钥，可解密 LLM Manager 存储的渠道 API 密钥 |

## 三、建议处理方案

### 方案 A：轮换密钥（**第一步，必做**）

**原理**：历史重写只能"防止未来"，无法回收**已经**被 clone 过的历史。
即使当前私有，轮换是最彻底的兜底。

```bash
# 生成新 Fernet 密钥
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"

# 替换 DeepAnalyze/.env 与 CW_to_WB/.env 中的 LLM_MANAGER_ENCRYPTION_KEY
```

**代价**：
- 已加密存储的 LLM 渠道密钥**无法用新密钥解密**，需在 LLM Manager 重新配置渠道
- 影响范围：部署环境的 `llm_manager.db`（CVM 生产、本机开发）

**建议**：当前私有仓库可**暂缓执行**，待确定未来发布形态（继续私有 vs 开源）后再定。

### 方案 B：历史清理（`git filter-repo`，**开源前必做**）

仅清理含密钥的文件历史，**不动 node_modules**（体积冗余无安全风险，可接受）：

```bash
# 1. 备份镜像
git clone --mirror . ../DeepAnalyze_backup.git

# 2. 安装
pip install git-filter-repo

# 3. 删除历史中所有 .env 文件
git filter-repo --path .env --invert-paths --force

# 4. 将历史中密钥文本替换为占位符（保留审计文档，仅抹密钥）
git filter-repo --replace-text <(echo "<原 LLM_MANAGER_ENCRYPTION_KEY 值>==>**REDACTED**") --force
```

**注意**：
- 需对两个仓库 × 三个分支分别处理
- 全部 commit hash 改变 → 远端需 **force push**（工蜂 + GitHub）
- `filter-repo` 默认移除 `origin` remote（需重新添加）
- 已有 clone 需重新 clone

### 方案 C：当前最小动作（**建议现在执行**）

既然当前私有、无泄露风险，**无需立即重写历史**。建议现在只做：

1. **将本文档纳入知识库**，作为开源前的"安全清理 CheckList"（✅ 已完成）
2. 在 `release_readiness_plan.md` 中将密钥引用改为占位符（消除当前 HEAD 的明文）
   （该文档是审计记录，建议保留描述、仅替换密钥文本）
3. 待决定开源时，按方案 A + B 完整执行
